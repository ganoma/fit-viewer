# docs/ — 役割間の引き継ぎ場所

サブエージェント（`pm` / `architect` / `implementer`）はコンテキストが分離されているため、
**役割間の情報はすべてこのディレクトリのファイルを経由して渡す**。会話での口頭引き継ぎは必ず欠落する。

```
docs/
  requirements/  PM役が書く。何を作るか・作らないか
  design/        設計役が書く。どう作るか
```

## 流れ

1. PM役が `requirements/<機能名>.md` を書く
2. 設計役がそれを読み、`design/<機能名>.md` を書く
3. 実装役が設計書を読んでコードを書き、lint とビルドを通して動作確認する
4. PM役が受け入れ条件と実装を突き合わせ、`requirements/<機能名>.md` の末尾に判定を追記する

差し戻しは前の工程へ戻す。設計役が要件の穴に気づいたら設計書末尾に質問を積み、
実装役が設計の穴に気づいたら手を止めて報告する。下流が勝手に埋めない。

ファイル名は工程をまたいで同じ `<機能名>` を使うこと。
